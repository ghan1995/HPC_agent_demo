# HPC Agent 下一步设计待办

本文档用于记录尚需继续展开的体验设计工作。已经形成共识的内容继续记录在 `knowledge/decisions.md`；这里重点描述下一步需要设计、验证和补齐的界面与状态。

## 1. 产物生成、交付与动态图表

### 当前方向

- 对话内部分支持轻量预览，包括与当前结论直接相关的摘要数据、静态图表和适合在消息宽度内快速理解的信息。
- 长文件、完整报告、复杂图表和需要较大阅读空间的内容在右侧 Inspector 查看。
- 科学计算作业运行过程中持续产生的动态数据，在右侧 Inspector 中以实时刷新图表展示。
- 对话流不承载持续刷新的完整图表，只显示运行状态摘要、关键变化、数据更新时间和“查看实时数据”入口。
- 产物和图表需要与当前作业、Run、数据来源和更新时间建立可追溯关联。
- 产物归属于 Task，不限于任务结束时生成；长时间科研数据处理过程中产生的数据、图表和阶段性结果也作为中间产物保留。
- 对话回答使用“本次生成 N 个产物”的集合卡片进行交付；单个产物点击后在右侧 Inspector 中查看。
- 当前 Session 提供独立的悬浮产物面板，集中记录 Task 运行中和完成后产生的全部产物。

### 下一步需要设计

1. 定义哪些产物允许对话内预览，以及进入右侧 Inspector 的判断标准。
2. 设计对话内静态图表的尺寸、标题、图例、数据时间范围、异常提示和展开入口。
3. 设计长文件在右侧 Inspector 中的目录、搜索、版本、下载和定位体验。
4. 设计实时图表的加载、刷新、暂停、断连、延迟、无数据、异常和作业结束状态。
5. 明确实时刷新是否自动滚动、刷新频率如何表达，以及用户查看历史区间时是否暂停自动跟随。
6. 设计对话摘要与右侧图表之间的联动，例如点击异常峰值后定位到对应时间点。
7. 明确多个图表、多个 Run 或多个作业并存时的切换和对比方式。
8. 验证图表在 Inspector 收起、窄屏和移动宽度下的降级方案。
9. 定义中间产物的更新、冻结、失败、过期和版本保留规则。
10. 明确多个 Task 共存时，悬浮产物面板的分组、排序和筛选方式。

### 需要补齐的 Demo 状态

- 对话内多产物集合卡片。（Demo 已实现）
- 记录运行中与任务完成后产物的悬浮面板。（Demo 已实现）
- 对话内静态图表预览。
- 从对话预览打开右侧完整图表。
- 长文件在 Inspector 中查看。
- 作业运行中的实时动态图表。
- 实时数据断连、延迟和恢复。
- 作业完成后从实时模式切换为可回看的历史结果。

### 完成标准

- 用户能在对话中快速理解结论，不必为每个简单图表打开侧栏。
- 长内容和动态图表不会持续拉长或扰动对话流。
- 用户能判断数据属于哪个作业和 Run，并知道数据是否仍在刷新、何时更新。
- 从对话摘要进入 Inspector 后，能直接定位到相关产物、图表或时间点。
- 用户能在任务运行期间及结束后找到全部产物，并区分持续更新的中间产物和已固化的最终产物。

## 2. 从作业页面进入后的上下文继承与解除

### 当前方向

- 用户从作业详情页进入 HPC Agent 时，可以继承当前集群、作业、来源页面和数据更新时间。
- 被继承的上下文必须在界面中明确可见，不能在后台静默影响回答或执行。
- 用户始终通过统一 Agent 入口描述目标，不需要先选择专业 Agent。

### 下一步需要设计

1. 明确进入 Agent 时继承哪些信息：作业 ID、集群、队列、项目、页面筛选条件、选中时间范围和临时状态。
2. 定义继承上下文的有效期，以及数据过期、作业删除或权限变化时的提示与处理。
3. 定义新问题与当前作业仍相关时，系统继续沿用上下文的判断方式。
4. 定义用户明显切换话题时的解除时机：自动解除、先提示确认，还是继续保留但降低绑定强度。
5. 设计用户主动查看、切换、更新和清除当前对象的入口。
6. 明确用户提到另一个作业 ID 时，是自动切换、同时保留多个对象，还是先请求确认。
7. 设计一个任务涉及多个作业、节点或队列时的上下文展示方式。
8. 定义 Session 再次打开时是否恢复原上下文，以及来源对象状态已变化时如何更新。
9. 明确解除上下文后，已有消息、Task、Run、产物和审计记录如何继续标记原对象关系。
10. 设计从 Agent 返回原作业页面时的路径、页面状态恢复和定位方式。

### 重点状态场景

- 从作业详情进入后直接询问当前作业。
- 连续追问，继续使用同一作业上下文。
- 用户开始咨询无关的集群通用问题。
- 用户主动清除或切换当前作业。
- 用户在消息中提到另一个作业。
- 当前作业已删除、无权限或数据已过期。
- 一个任务需要比较多个作业。
- 历史 Session 恢复时，来源作业状态已经变化。

### 完成标准

- 用户始终能看见当前回答和操作绑定的对象。
- 系统不会因为隐式继承旧作业而对错误对象执行操作。
- 上下文切换和解除不会破坏原有 Task、Run、产物与审计记录的可追溯性。
- 普通连续追问不需要用户反复选择同一作业；话题明显变化时也不会被旧上下文强行限制。

## 3. 与 SE 共建完整典型任务流和 Demo 故事线

### 目标

联系 SE，获得一个业务真实、步骤完整且适合演示的典型 HPC 任务流，作为后续 Demo 的统一故事线，避免各页面和组件只展示互不关联的局部状态。

### 需要 SE 补充的信息

1. 典型用户角色、业务目标和任务触发背景。
2. 用户进入 Portal 前已经掌握的信息，以及从哪个页面或对象进入 Agent。
3. 从提出目标到任务完成的完整步骤，包括查询、分析、参数准备、确认、执行和结果验证。
4. 会调用的真实系统、工具、数据来源和关键输入输出。
5. 任务中可能出现的等待、失败、权限不足、数据异常和人工确认节点。
6. 用户判断任务成功的标准，以及任务完成后的常见下一步。
7. 哪些步骤适合由多个专业 Agent 并行完成，哪些必须串行执行。
8. 可用于 Demo 的脱敏业务数据、参数、日志、图表和产物示例。

### 下一步设计工作

- 将 SE 提供的任务流整理为一条主故事线，并补充关键分支。
- 标注每个阶段对应的对话、思考过程、Agent、工具、确认、Task、产物和 Inspector 状态。
- 确定 Demo 的起点、关键转折、用户操作、最终结果和演示时长。
- 统一当前首页、历史会话、诊断、重新提交、实时数据和产物查看中的对象与数据。

### 完成标准

- Demo 从进入 Agent 到完成任务形成连续、可信的业务叙事。
- 每个界面和状态都能对应故事线中的明确节点。
- 主流程和关键异常分支都有真实业务依据，不依赖临时拼接的示例。

## 4. 补齐运行态、加载态和过程反馈

### 目标

建立覆盖任务启动、持续运行、等待、流式输出、局部刷新和完成切换的统一状态表达，使用户能理解系统正在做什么、是否仍在工作以及是否需要自己行动。

### 下一步需要设计

1. 首次响应前的加载状态，以及从用户提交到出现思考过程之间的反馈。
2. 思考文本、工作步骤、Agent 和工具调用的流式出现方式。
3. 短时运行与长时任务的差异化反馈，避免所有任务使用相同加载动画。
4. Agent 并行运行、部分完成、等待外部系统和重试中的状态组合。
5. 数据查询、文件加载、图表初始化和实时数据刷新等局部加载状态。
6. 等待用户确认、等待用户补充信息和等待外部系统三类等待状态的区别。
7. 网络中断、工具超时、恢复连接、自动重试和人工重试的反馈方式。
8. 从运行态切换到完整结论时，思考过程折叠和结果出现的动效与时序。
9. 低动态偏好、键盘操作和屏幕阅读器下的替代表达。

### 需要补齐的 Demo 状态

- 首次加载与响应准备。
- 思考过程和回答的流式生成。
- 多 Agent 并行、部分完成和长时间运行。
- 等待确认、等待输入和等待外部系统。
- 局部内容加载与实时数据刷新。
- 超时、断连、重试、恢复和失败。
- 运行完成后折叠过程并输出结论。

### 完成标准

- 任意时刻用户都能判断系统是否仍在运行、当前阶段是什么、是否需要行动。
- 页面不会因为多个区域同时刷新而频繁跳动或抢夺用户注意力。
- 状态不只依赖颜色，且加载反馈不会被误解为系统卡死。

## 5. 统一设计右侧 Inspector

### 目标

对当前尚未系统设计的右侧面板进行统一规划，使产物、证据、上下文、日志、复杂图表和实时数据共享一致的框架与交互规则。

### 下一步需要设计

1. Inspector 的统一标题栏、对象信息、状态、关闭、返回和更多操作。
2. 产物、证据、上下文、运行日志、比较和实时图表等内容类型的导航方式。
3. 从对话、Task、思考过程和上下文区打开 Inspector 时的定位与返回关系。
4. 同一内容在不同入口打开时，是否复用当前面板状态。
5. 面板宽度、可调整尺寸、全屏查看和窄屏覆盖模式。
6. 长内容滚动、目录、搜索、筛选、时间范围和下载操作。
7. 加载、空数据、无权限、数据过期、断连和错误状态。
8. 实时图表刷新时的稳定性，以及关闭面板后是否继续更新。
9. 多个对象、产物或图表之间的切换和历史返回。
10. Inspector 使用页签承载多个产物、证据和运行日志，并支持整体展开与收起；收起后的恢复入口始终固定在页面最右侧。（Demo 已实现）

### 完成标准

- 不同内容类型使用同一套面板骨架、导航和状态反馈。
- 用户能理解当前查看的对象、来源、更新时间及其与对话或任务的关系。
- 打开和关闭 Inspector 不会破坏对话阅读位置或正在进行的任务。

## 6. Portal 随行模式

### 当前方向

HPC Agent 除了独立的大屏工作模式，还需要在 Portal 页面提供随行模式。随行模式服务于用户查看作业、集群、节点、队列等业务页面时的即时询问和辅助操作。

### 下一步需要设计

1. 随行模式在 Portal 中的入口、默认位置、展开尺寸和收起方式。
2. 随行模式与当前页面对象、筛选条件和选中内容的上下文继承。
3. 哪些轻量查询和操作可以直接在随行模式完成，哪些需要转入大屏模式。
4. 从随行模式进入大屏模式时，对话、上下文、草稿、Task 和运行状态的连续性。
5. 从大屏模式返回 Portal 时，原页面位置、筛选和选中对象如何恢复。
6. 长任务、复杂产物、右侧 Inspector 和实时图表在随行模式中的降级或跳转方式。
7. 随行模式中的确认操作、权限提示和高风险操作边界。
8. Portal 页面空间不足、遮挡业务内容和窄屏情况下的布局策略。
9. 同一 Session 是否可以在随行模式和大屏模式之间持续同步。

### 建议职责边界

- 随行模式：快速提问、解释当前页面、轻量查询、查看任务摘要和发起常见操作。
- 大屏模式：复杂任务编排、多轮分析、完整过程审计、长文件、复杂图表、实时数据和多任务管理。

### 完成标准

- 用户在 Portal 当前工作场景中可以快速获得帮助，不必为简单问题离开页面。
- 任务变复杂时可以无损切换到大屏模式，不丢失上下文和运行状态。
- 两种模式职责清晰，不重复实现两套互相独立的 Agent 体验。
