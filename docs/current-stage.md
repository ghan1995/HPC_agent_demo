# HPC Agent 当前阶段工作进展与实现约束

> 基线日期：2026-09-21
> 阶段：前端可交互 Demo
> 状态：首轮组件化和视觉重构完成

## 1. 阶段结论

项目已从工程初始化进入可评审的前端原型阶段。当前已完成 Session 管理、新对话首页、对话展示、可审计工作过程、工具与子 Agent 详情、任务托盘、操作确认和 Inspector。

当前不包含真实 HPC 后端、Agent Runtime、调度器、监控、日志、知识库或模型调用。所有业务数据、工具输出和执行结果都是可复现的本地演示状态。

## 2. 已完成能力

### 2.1 Session 侧栏

- “需要处理”置顶，其他 Session 按项目分组。
- 每条 Session 保持单行“状态 + 标题”。
- 项目、状态和更新时间在悬浮卡中展示。
- 悬浮时显示更多操作，支持搜索、新建、选择、收起、重命名和归档。
- 分组文件夹和其他图标使用统一 SVG 尺寸并继承文字颜色。

### 2.2 新对话首页

- 提供四个可直接填充输入框的推荐任务。
- 每张卡片使用不同的低透明度单色径向渐变；渐变圆心在卡片左上角外侧。
- 卡片图标不使用额外色块背景，文字和边框保持中性。

### 2.3 输入区

- 支持文件、文件夹、执行审查策略和提交。
- 审查图标与文字合并为同一菜单按钮，内部间距为 4px。
- 输入区默认为纯白、100% 不透明，不会因为发送按钮禁用而整体变灰。
- 空内容时只有提交按钮表达禁用状态。

### 2.4 对话与工作过程

- 使用 `Conversation` 管理滚动和回到底部。
- 使用 `Message`、`MessageContent` 和 `MessageActions` 展示消息、复制和反馈。
- “思考过程”是正式结论之前唯一的一级过程容器；工作过程与 Agent 协作作为容器内的两个关联视图，共享同一次运行状态。
- 思考过程展开后先展示简短、可审计的分析摘要文字，再展示工作步骤和 Agent 协作；这些文字是用户可理解的判断摘要，不是模型私有原始思维。
- 工具节点展示名称、状态、输入、输出和错误。
- 子 Agent 可逐个展开，展示职责、状态、耗时、真实输入输出和工具；模型、指令摘要和可用工具位于二级配置。
- 完整结论输出后，思考过程自动折叠为耗时、活动数与 Agent 数量摘要；运行中、等待确认或失败时保持展开。用户手动操作后，普通状态更新不抢夺展开控制。
- 操作确认卡独立位于思考过程之外，即使过程折叠也始终可见。
- 等待确认阶段不提前输出最终结论；确认后继续执行，思考过程完成并收起，再输出正式结果。拒绝时只输出取消结果，不伪造执行结论。

### 2.5 任务托盘与 Inspector

- 任务托盘位于输入框上方，与输入框连接成整体。
- 收起时为紧凑单行；展开后标题固定，任务列表最多显示约三条，超出后内部滚动。
- 报告、运行日志、资源证据和历史运行比较复用右侧 Inspector。
- 提交确认支持批准、拒绝和模拟新作业结果。

## 3. 组件边界

### 3.1 AI Elements

使用 `Conversation`、`Message`、`ChainOfThought`、`Tool`、`Agent`、`Task`、`Plan`、`Confirmation`、`Artifact` 和 `PromptInput` 表达 AI 对话与运行语义。

### 3.2 shadcn/ui

使用 `Button`、`Badge`、`Tooltip`、`HoverCard`、`DropdownMenu`、`Dialog`、`Collapsible`、`Separator`、`InputGroup`、`Select` 和 `Card` 表达通用交互和基础视觉。

### 3.3 HPC 业务组件

继续由项目自定义维护：Session 项目分组、集群上下文、作业诊断摘要、资源证据、历史运行比较、运行过程编排、任务托盘、Inspector 和应用外壳。

约束：优先复用已安装组件和现有 variant，不在业务组件中重复实现菜单、弹窗、提示、折叠和按钮等通用能力。

## 4. 数据模型

统一类型位于 `src/features/hpc-agent/types.ts`：

- `RunEvent`：阶段摘要、工具、参考资料和关联 Subagent ID 等运行事件。
- `ToolRun`：工具名称、状态、输入、输出和错误。
- `SubAgentRun`：职责、状态、耗时、配置和真实输入输出。
- `RunTrace`：一次完整的可审计思考过程，统一承载工作事件、Subagent、披露状态和 Demo 运行帧。
- `TaskPlan`：当前任务及步骤。
- `ApprovalState`：等待、批准和拒绝。
- `SessionGroup` 与 `SessionItem`：Session 分组及单项数据。
- `InspectorMode`：报告、证据、比较和日志视图。

接入真实接口时，优先让后端数据适配这些模型，不在渲染组件内拼装临时数据结构。

## 5. 视觉 Token 与样式约束

### 5.1 中性 Token

- `--background` / `--foreground`：页面背景和主要文字。
- `--card` / `--card-foreground`：内容表面。
- `--muted` / `--muted-foreground`：次级表面和辅助文字。
- `--border` / `--input` / `--ring`：边框、输入控件和焦点。
- `--sidebar-*`：侧栏背景、文字、选中、边框和焦点。

业务组件不再新增分散的十六进制灰阶，优先使用语义 Token 或基于 Token 的 `color-mix()`。

### 5.2 状态色

- `--status-running`：运行蓝。
- `--status-complete`：完成绿。
- `--status-waiting`：等待琥珀。
- `--status-error`：失败红。

普通按钮、图标、标题和文本保持中性。状态色不是唯一信息载体，必须同时提供文字、图标或结构。

当前推荐卡片暂时借用四个状态 Token 作为极低透明度的装饰色。设计系统固化时应拆成独立的 `--suggestion-accent-*` Token，避免装饰色与运行语义耦合。

### 5.3 层级、字体与图标

- 页面背景、侧栏/次级区域、内容表面、悬浮层构成四级表面。
- 普通分区优先使用底色和 1px 边框；阴影主要用于菜单、悬浮卡、输入区和覆盖面板。
- 正文以 14px 为主，辅助信息不低于 12px，紧凑状态标签可使用 11px。
- 标题层级固定为页面标题、模块标题、正文和元数据四档。
- 图标使用 Lucide SVG 并继承 `currentColor`；按钮内图标使用 `data-icon`。
- 不为普通图标随意增加彩色方形背景。

### 5.4 布局

- Session 侧栏基准宽度约 252px。
- 对话与输入阅读宽度约 760px。
- Inspector 保持独立层级；窄屏使用覆盖式面板。
- 任务托盘和输入框必须保持连接，不允许中间出现无意义空隙。
- 页面不得产生水平滚动，窄屏必须保留核心操作。

## 6. 交互、安全与可审计约束

- 不展示模型私有原始思维，只展示可审计的判断摘要、阶段、工具和 Agent 输入输出。
- 真实工具节点必须展示实际调用名称，接入后端后不得伪造调用结果。
- 子 Agent 必须可逐个展开，不能只展示汇总数量。
- 写操作、重新提交和其他产生外部影响的行为必须使用 `Confirmation`。
- 不得将“重新生成回答”、“重新分析”和“重新执行写操作”混为一个按钮。
- 悬浮、菜单、展开、Inspector 和输入控件必须保留键盘焦点、ARIA 标签和颜色对比度。
- 当前未接入业务 API，所有提交和执行结果必须明确属于本地演示。

## 7. 工程约束

- Next.js 使用 16.3.5；修改框架相关实现前必须阅读当前安装版本的 `node_modules/next/dist/docs/`。
- 优先复用已安装的 AI Elements 和 shadcn/ui，再新增 HPC 业务组件。
- 视觉 Token 统一维护在 `src/app/globals.css`。
- 本地演示数据和类型与渲染组件分离。
- 页面或交互变更至少运行 `pnpm typecheck`、`pnpm lint` 和 `pnpm build`。
- 不将 `.env*`、密钥、未脱敏数据、构建输出或本地依赖提交到 Git。
